# Integrated R1/R2 evaluation

**R4 update (2026-11-03):** the complete, provisional comparison is in
[`evaluation/part4/r4_results_v2/REPORT.md`](evaluation/part4/r4_results_v2/REPORT.md).
All 554 current pooled pairs now have explicit grades: 40 submitted human reviews,
192 reused AI judgments and 322 new AI metadata drafts. Both submitted review
sets (150 pairs across 50 queries) are preserved and audited. This is a mixed
human/AI evaluation, not the fully manual study described in the proposal.

`retrieval/evaluation/integrated.py` compares BM25, semantic Qwen retrieval,
the final R1 hybrid (`FinalRetriever`), and that same R1 path with R2 feedback.
It invokes `MusicIntelligence.handle()` and the production `MusicService` adapter;
it does not reimplement the feedback ranker in a separate benchmark.

All 50 distinct queries are loaded from Tobi's and Janani's existing files. Every
method gets the same playlist and hard exclusions, including known songs and
matching remasters. Only `hybrid_feedback` receives soft positive/negative votes.
Each timed request starts with fresh conversation state, and repeated rankings
must match. Excluded final tracks or duplicate results abort the run.

This is a ranking benchmark of the standard application route. The optional
external LLM route is verified separately by both scripted Socket.IO checks and
the completed live Ollama check (11 provider calls, 14 checks over 15 turns), in
`evaluation/part4/live_llm_check_v1/`. Those calls do not supply R4 quality metrics
or the timing samples below. Non-command prompts such as “Find …” are
prefixed with “Recommend” uniformly across methods; the original query and exact
application request are recorded. This does not measure intent-recognition quality.

The application returns up to five tracks. The relevance pool unions those top
five tracks across all four methods for each query. All methods must ultimately
be scored against this same pool. Short lists are retained, with Precision@5
dividing by five. Relevance grades are not inferred from retrieval scores.

The run makes three warm measurements per method/query, giving 200 rankings and
600 timing samples. Timing covers conversation handling, natural-language
constraint resolution, retrieval, feedback, explanations and recommendation
payload construction. Schema preparation, model/index initialization, network
transport and browser rendering are excluded. Initialization is recorded separately.
These timings share one boundary; older standalone experimental timings differ.

## Commands

Set `HF_HOME` to the repository's absolute `cache/huggingface` path if needed.
Use a new output directory; the runner refuses to overwrite prior runs.

```bash
HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 MUSICCRS_NLU_LOCAL_ONLY=1 \
  .venv/bin/python -m retrieval.evaluation.integrated run \
  --output-dir evaluation/part4/integrated_evaluation_new \
  --repeats 3 \
  --judgment-sources \
    evaluation/part4/adaptive_evaluation_v1/reviewed_judgments.csv \
    evaluation/part4/janani_results/judgments.csv

# Run only after every pooled row has an explicit 0–2 grade and assessor.
.venv/bin/python -m retrieval.evaluation.integrated score \
  --directory evaluation/part4/integrated_evaluation_new \
  --judgments evaluation/part4/integrated_evaluation_new/judgments.csv \
  --output evaluation/part4/integrated_evaluation_new/metrics.json

# Replay the recorded requests against current code without creating labels.
.venv/bin/python -m retrieval.evaluation.integrated verify \
  --directory evaluation/part4/integrated_evaluation_new \
  --output evaluation/part4/integrated_evaluation_new/replay_verification.json
```

## Artifacts and judgment provenance

- `runs.json`: resolved query contexts, exact application requests/replies, final
  rankings, timing samples, feedback evidence and implementation source hashes.
- `human_review_blank.csv`: complete blinded pool with blank grade, reason and
  assessor fields. No method, ranking or retrieval-score columns are included.
- `judgments.csv`: copies existing judgments only for identical query/track pairs
  whose context and catalog metadata also match. Their original assessor identity
  is retained. New or mismatched candidates remain blank.
- `coverage.json`: reused/missing judgments, assessor counts, warm latency and
  exclusion checks. Its timing statistics require no relevance labels.
- `environment.json`: startup/warmup duration and the actual Qwen model name.

No new relevance labels are generated by this runner. Existing labels are
AI-assisted, not manual human ground truth. The scorer now recognises Janani's
`AI-assisted:metadata-only:PROVISIONAL` format as AI assessment; it no longer
reports those rows as human assessor labels. UTF-8 CSVs with an Excel BOM are
accepted. Unjudged pooled rows prevent scoring instead of becoming zero grades.

Human review of 75 sampled pairs can support an agreement/label-quality study.
It cannot turn the full pooled evaluation into the manually judged study in the
approved proposal. Complete the agreed manual judgments, or explicitly document
an accepted sampling deviation, before presenting final relevance conclusions.

## Completed R4 calculations

`retrieval/evaluation/r4_finalize.py` reads submitted CSV/XLSX reviews, validates
query/track/context identity, gives human reviews precedence for the same pair,
and records every correction. It accepts only literal review grades, rejects
duplicate/conflicting inputs and formula grades, and refuses to overwrite output.
AI decisions must cover exactly the missing pairs and match frozen input hashes.
The original reviewers' files are copied unchanged into `source_reviews/`.

Janani supplied 75 judgments for Tobi's older pool, and Tobi supplied 75 for
Janani's older pool. Each set contains three judgments for each of 25 queries.
Exact agreement with previous AI grades is 65/75 (86.7%) and 61/75 (81.3%). Only
40 reviewed pairs overlap the newer integrated pool, so human review covers
7.2% of its 554 pairs. Four of those current-pool AI grades were corrected.
One submitted row had UTF-8 text decoded as Mac Roman; three metadata fields
were restored only because the reversible transformation exactly matched the
frozen evidence. Its human grade was preserved.

Only 11 of the 75 returned Tobi-pool pairs match the originally exported seeded
sample. The returned set is still three per query, but it must not be described
as that original random sample. The agreement figures describe submitted pairs;
they do not establish population accuracy, inter-human agreement or full blinding.

| Method | nDCG@5 | Precision@5 | Mean warm backend ms |
| --- | ---: | ---: | ---: |
| BM25 | 0.8650 | 0.9440 | 207.8 |
| Qwen semantic | 0.6236 | 0.7920 | 514.5 |
| R1 hybrid | 0.8636 | 0.9400 | 853.9 |
| R1 hybrid + R2 feedback | 0.9259 | 0.9520 | 846.6 |

These are **provisional mixed-judgment results**. On the ten feedback queries,
nDCG@5 changes from 0.6266 to 0.9378, a paired mean difference of +0.3112.
Precision@5 improves by +0.0600. Seven queries improve in nDCG and three tie;
two improve in precision and eight tie. All 40 non-feedback query rankings are
unchanged by the feedback variant. This is a controlled comparison with the
same known-track exclusions, rather than a longitudinal user study. No system
was retuned or grade chosen to obtain an improvement. BM25 and hybrid without
feedback are very close; hybrid does not beat BM25 in this table.

The independent standard-library calculation matches method averages to within
1.2e-16 and agrees with the paired feedback deltas. All 2,216 title/artist/album/tag
comparisons against the current catalog pass, and all 987 returned tracks across
200 rankings pass the hard-exclusion recheck. Timings remain the frozen 600
samples; report generation does not measure new latency or include the external LLM.

Reproduce the results using the preserved review inputs and a fresh output path:

```bash
.venv/bin/python -m retrieval.evaluation.r4_finalize \
  --directory evaluation/part4/integrated_evaluation_v2 \
  --human-reviews \
    evaluation/part4/r4_results_v2/source_reviews/1_Tobi_75_Combined_Submitted_Reviews.csv \
    evaluation/part4/r4_results_v2/source_reviews/2_Janani_75_Blind_Human_Review_For_Tobi.xlsx \
  --ai-decisions evaluation/part4/r4_results_v2/ai_decisions.json \
  --output-dir /tmp/musiccrs-r4-reproduced
```

The result pack contains the report, machine-readable metrics/category and
per-query results, every merged grade with its original provenance, submitted
source files, draft decision manifest, validation and catalog/exclusion audits.
Earlier audit/draft reports remain local and are omitted from the submission
changes. V2 is the current report, with the original source judgments preserved
in `integrated_evaluation_v2/judgments.csv`.

The computational R4 work is complete. The remaining research limitation is
human assessment: the proposed full-manual evaluation would require reviewing
the other 514 current-pool pairs, or explicit acceptance of the sampled-human,
AI-assisted protocol. Metadata-only labels can favor lexical retrieval and do
not prove how relevant songs sound. The actual semantic model is Qwen, rather
than the proposal's Sentence-BERT, and this difference is disclosed in the report.
Tobi confirmed after discussing it with Janani that Qwen is the team's revised
encoder choice; see [R1_REVIEW_FIXES.md](R1_REVIEW_FIXES.md).
